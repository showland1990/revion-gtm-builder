# GTM Routing Rules

## Foundation gate
Before scaling PLG, marketing, outbound or enterprise sales, check ICP, pain + trigger, buyer/champion, value, differentiation/proof and motion architecture. If weak, route upstream.

## Symptom router
- fuzzy audience → `who-is-this-for` or `segmentation`
- assumptions dominate → `talk-to-users`
- generic positioning → `positioning-and-story` / `messaging-house`
- weak defensibility → `beyond-the-wrapper`
- weak homepage → `the-homepage`
- first-run leak → `time-to-first-value`
- full activation system → `activation-and-onboarding`
- first users → `first-50-users`
- first deals → `founder-led-sales`
- repeatable enterprise → `sales-led-strategy`
- signups but no revenue → acquisition quality → activation → retention → monetization → PQL/PQA
- bad PQLs → `pql-pqa-model`
- need pipeline → demand capture/product signals/account selection before outbound
- stalled deal → `opportunity-inspection`
- marketing busy, pipeline flat → `revenue-marketing-review`
- ABM request → run ABM gate
- forecast/data distrust → `revops-strategy`
- next priority unclear → `strategy-and-roadmap`

## Never
- scale acquisition into weak retention
- write generic outbound without ICP + trigger + persona + proof
- call usage alone a PQL
- call a friendly user a champion without evidence
- call a meeting an opportunity automatically
- manufacture ROI
- claim attribution is causal without stronger evidence
- apply a universal pipeline coverage multiple
- let teams silently redefine lifecycle stages
