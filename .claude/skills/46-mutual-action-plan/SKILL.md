# Mutual action plan

> A MAP is useful only when it is genuinely mutual. A vendor project plan disguised as collaboration is not a MAP.

## Anchor to customer event

Start with:
- target business outcome/event
- required live date
- decision date
- implementation lead time

Work backward.

## Typical milestones

- discovery complete
- technical evaluation
- success criteria met
- security review
- business case
- economic approval
- legal
- procurement
- signature
- implementation
- go-live

Delete irrelevant steps.

## Every milestone needs

- outcome
- customer owner
- vendor owner
- date
- dependency
- status

## MAP test

The customer should:
- agree it reflects their process
- own some actions
- correct dates/process
- use it internally

If only the seller updates it, it is probably not mutual.

## Output

Write `docs/gtm-cofounder/opportunities/<account>-map.md` or embed in opportunity file.
