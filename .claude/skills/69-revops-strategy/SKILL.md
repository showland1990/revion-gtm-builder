# RevOps strategy

> RevOps makes the revenue system legible. It is the operating contract between product, marketing, sales and customer teams.

Read first:
1. `docs/gtm-cofounder/gtm-context.md`
2. `docs/gtm-cofounder/plg-model.md`
3. `docs/gtm-cofounder/revenue-marketing-model.md`
4. `docs/gtm-cofounder/sales-model.md`
5. existing attribution, scorecards and roadmap
6. CRM/product/data architecture if available

## RevOps jobs

1. Define common objects and identities.
2. Define common lifecycle and stage states.
3. Define ownership and handoffs.
4. Make funnel math trustworthy.
5. Connect activity to pipeline and revenue.
6. Build forecasting discipline.
7. Build unit-economics visibility.
8. Create operating reviews that change decisions.

## RevOps is not admin

Do not optimize for:
- number of fields
- dashboard count
- CRM cleanliness without decision value

Optimize for:
- fewer conflicting definitions
- faster handoffs
- higher data confidence
- clearer constraints
- better forecastability
- better economics
