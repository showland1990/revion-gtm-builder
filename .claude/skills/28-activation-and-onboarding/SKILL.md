# Activation and onboarding

> Onboarding is not a tour. It is the shortest reliable path from intent to realized value.

Read the existing `time-to-first-value` skill for first-run friction principles.

## Separate three moments

### Setup complete
The product is technically ready.

### Aha
The user understands why it matters.

### Activation
The user has actually performed behavior predictive of future value.

They may occur at different times.

## Find activation empirically where possible

Compare retained vs churned cohorts:
- Which early actions are disproportionately common among retained users?
- In what sequence?
- Within what time window?
- At user or account level?

Do not define activation solely from founder intuition if usage data exists.

## Activation criteria

A good activation event:
- represents delivered value
- happens early enough to optimize
- predicts retention
- is not trivially gamed
- is instrumentable
- works at the correct unit

Composite activation is valid, e.g. `integration connected + first successful run + second run within 7 days`.

## Onboarding architecture

Map:
1. intent
2. required setup
3. first value
4. reinforcement
5. next repeated behavior
6. collaboration/team step if applicable

For each step capture user question, friction, proof/reassurance, product guidance, lifecycle assist and metric.

## Progressive onboarding

Do not teach the whole product. Reveal complexity when the user's job requires it.

## Human assist

If high-value accounts fail due to unavoidable complexity, define assisted onboarding rather than pretending PLG must mean zero humans.

## Output

Update `plg-model.md` with setup event, aha, activation event/window, time-to-value, baseline, segment splits, friction, onboarding and assisted paths. Route tactical first-run fixes to `time-to-first-value`.
