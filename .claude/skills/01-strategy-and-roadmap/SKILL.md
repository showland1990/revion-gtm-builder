# Strategy and roadmap

> The catalog contains moves. This skill decides what deserves attention now.

## Read first

1. `founder-brief.md`
2. `gtm-context.md` if available
3. `foundation-review.md` if available
4. current functional models
5. current roadmap

If context is absent, use `start-here`.
If the user has a broad symptom and the root cause is unclear, use `gtm-orchestrator`.

## Diagnose one company constraint

Examples:
- unvalidated ICP/pain
- weak category/message
- poor acquisition quality
- activation
- retention
- monetization
- PQL quality
- pipeline creation
- opportunity quality
- champion/business case
- enterprise process
- expansion
- data/forecast confidence

Do not pick one company constraint per function. Pick one company-level constraint.

## Founder Mode

Use when a small team cannot execute many priorities in parallel.

- Diagnosis
- Now: one move
- Next: 2-3
- Later
- Learning log

## GTM Team Mode

Use when multiple functions can work concurrently.

Allow maximum one active priority per:
- Product Marketing / Foundation
- PLG / Growth
- Revenue Marketing
- Outbound
- Sales
- Customer / Expansion
- RevOps

Every active item needs:
- problem
- skill
- owner/function
- metric
- baseline if known
- done looks like
- dependency
- evidence gained

## Routing rules

Use original skills when they are the sharpest narrow tool.
Use expansion skills for deeper operating systems.

Examples:
- early fuzzy ICP → `who-is-this-for`
- full market segmentation → `segmentation`
- first-run friction → `time-to-first-value`
- full activation system → `activation-and-onboarding`
- first customers → `founder-led-sales`
- repeatable enterprise system → `sales-led-strategy`
- early measurement → `know-if-its-working`
- cross-functional data/forecast → `revops-strategy`

## Foundation gate

Do not scale PLG, marketing, outbound, or enterprise execution when foundation review shows critical red gaps in:
- ICP
- pain/trigger
- buyer/champion
- value
- differentiation/proof
- motion

## Persist

Write `docs/gtm-cofounder/gtm-roadmap.md`.

After meaningful work:
- log the learning
- update evidence status
- update GTM context if a foundational belief changed
- promote/re-route the next move

The user should never need to browse the skill catalog to know what to do next.
