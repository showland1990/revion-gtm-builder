# GTM foundation review

> A polished strategy built on guesses is more dangerous than an unfinished one.

Read `docs/gtm-cofounder/gtm-context.md` as a skeptic.

## Review for contradictions

Examples:
- "self-serve PLG" but implementation requires security review
- "developer buyer" but ACV requires VP approval
- "enterprise ICP" but no enterprise proof
- "urgent pain" but no trigger event
- "unique" differentiation that every competitor also claims
- "usage pricing" where usage does not correlate with value
- "PQL" defined by volume rather than fit + value + intent
- "ABM" with low ACV or a huge undifferentiated TAM

## Score the foundation

Use Red / Amber / Green:

1. Market/category
2. Segmentation
3. Primary ICP
4. Pain
5. Trigger / why now
6. JTBD
7. User/adopter
8. Champion
9. Economic buyer
10. Buying process
11. Value
12. Quantification
13. Proof
14. Differentiation
15. Pricing
16. PLG mechanics
17. Sales mechanics
18. PQL/PQA handoff
19. Revenue-marketing lifecycle
20. Funnel definitions / measurement

## Evidence test

For each foundational belief ask:
- what is the evidence?
- is it independent?
- is it repeated?
- is it recent?
- does it come from the target segment?
- is behavior stronger than stated preference?

## Produce

### What is strong
Only evidence-backed strengths.

### What is weak
Specific gaps.

### Contradictions
State them plainly.

### Highest-risk assumptions
Maximum five.

### Validation plan
For each high-risk assumption:
- question
- evidence needed
- best source
- cheapest test
- decision it unlocks

### Ready/not ready gates

**Ready for messaging execution** when ICP, pain, category, value and proof are coherent.

**Ready for PLG execution** when activation, retained behavior, monetization and instrumentation are defined.

**Ready for outbound** when account criteria, trigger, persona, problem hypothesis and proof are defined.

**Ready for enterprise sales** when buying committee, discovery, evaluation, champion, business-case and procurement paths are defined.

**Ready for RevOps scaling** when funnel objects, stages and handoffs are consistent.

Then hand the reviewed foundation to `strategy-and-roadmap`.
