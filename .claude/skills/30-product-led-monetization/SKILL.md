# Product-led monetization

> Monetization should appear when the customer has earned value and a new constraint or higher-value need emerges.

Read `pricing` for value metric and packaging principles.

## Monetization prerequisites

Before optimizing paywalls ask:
- Do users activate?
- Do they retain?
- Is the primary segment economically valuable?
- What product behavior predicts willingness to pay?
- Who controls spend?

## Identify upgrade moments

Common categories:
- scale
- collaboration
- governance
- trust/security
- advanced workflow
- automation
- support
- deployment/control
- usage

For each upgrade moment capture value already received, new need, user, buyer if different, friction, CTA and self-serve vs assisted path.

## Paywall taxonomy

- Hard gate: cannot continue. Use cautiously.
- Soft limit: can continue but constrained.
- Feature gate: higher-value capability.
- Organizational gate: SSO, governance, audit, security, procurement.
- Usage expansion: natural value/volume growth.

## Conversion path

Map:
`value experienced → trigger → plan/value explanation → checkout or sales assist → successful paid adoption`

Measure upgrade surface viewed, checkout started/completed, sales request, upgrade conversion by trigger, and post-upgrade retention.

## Avoid monetization dark patterns

Do not use surprise bills, hide core advertised value, create artificial urgency, make cancellation intentionally difficult or use confusing usage metrics.

## Output

Update monetization trigger matrix, free/paid boundary, self-serve boundary, assisted boundary, checkout friction and upgrade experiments. Route pricing-number decisions to `pricing`.
